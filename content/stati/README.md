# ТЗ и формат информационных статей `/stati/`

Раздел информационных статей: `content/stati/*.md` → `node scripts/build_articles.js` → `src/data/articles.js` → отдаётся на `/stati/` и `/stati/<slug>/`.

Сгенерированный `src/data/articles.js` **коммитится в git**. На проде сборка не запускается — нода просто читает модуль, как `src/data/gosts.js`.

---

## 1. Зачем этот раздел

Две задачи, обе измеримые:

1. **Попасть в ответы нейросетей** (AI Overviews, ChatGPT Search, Perplexity, Gemini, AI Mode, Copilot). Замер: Ahrefs `site-explorer-ai-responses-count`. Baseline на 2026-09-20 — 1 цитирование на все платформы.
2. **Собрать информационный трафик**, который сейчас уходит мимо: коммерческие страницы марок отвечают на «лента 12Х18Н10Т купить», но не на «12х18н10т расшифровка», «магнитится ли нержавейка», «плотность стали».

Отсюда главное правило: **страница должна отвечать на вопрос в первых 60 словах**, а дальше подтверждать ответ фактами. LLM цитирует короткие проверяемые утверждения с числами и ссылкой на норматив, а не подводки «в современном мире металлопрокат играет важную роль».

## 2. Требования к статье

| Параметр | Норма |
|---|---|
| Объём MAIN_TEXT | 900–1600 слов |
| H2-разделов | 4–7, каждый отвечает на отдельный вопрос |
| ANSWER | 40–60 слов, прямой ответ без вводных |
| KEY_FACTS | таблица 5–10 строк с числами и единицами |
| FAQ | 5–8 вопросов, ответ 1–3 предложения |
| Внутренних ссылок | 3–6 (марка, группа, ГОСТ, калькулятор) |
| SEO_TITLE | до 60 символов |
| SEO_DESCRIPTION | до 160 символов |

**Запрещено:**

- вода и маркетинговые штампы («широкий ассортимент», «в современном мире», «наша компания предлагает»);
- выдуманные числа. Химсостав, температуры, плотность, механические свойства — только из ГОСТ или марочника. Правило наследуем из `text/00_README_FOR_CURSOR.md`: **при сомнении пишем обобщённо** («около 28 % кобальта»), а не рискуем точной цифрой;
- копирование текста ГОСТов — тексты стандартов охраняются авторским правом. Пересказываем своими словами и ссылаемся на официальный источник;
- обещание того, чего нет в каталоге. Если тема шире нашего сортамента (например, монтажная перфолента) — честно объясняем разницу, а не делаем вид, что продаём.

**Обязательно:**

- единицы измерения у каждого числа (мм, °C, г/см³, мкОм·м, МПа, HRC);
- номер ГОСТа рядом с нормативным утверждением;
- дата актуальности (`updated` в META) — выводится на странице;
- перелинковка: из статьи в каталог (марка/группа), в ГОСТ и в калькулятор веса.

## 3. Формат файла

Имя файла: `<номер>_<slug>.md`, например `03_magnititsya-li-nerzhaveyka.md`. Номер задаёт только порядок в репозитории, на URL не влияет.

Секции размечаются `## КЛЮЧОМ ЗАГЛАВНЫМИ`. Обычные `## Заголовки` внутри MAIN_TEXT парсер не трогает — он реагирует только на список ключей: `META`, `SEO_TITLE`, `SEO_DESCRIPTION`, `H1`, `ANSWER`, `KEY_FACTS`, `MAIN_TEXT`, `FAQ`.

```markdown
# Рабочее название (в вывод не идёт)

URL: /stati/magnititsya-li-nerzhaveyka/

## META
- cluster: Марки и сравнения
- updated: 2026-09-20
- sources: ГОСТ 5632-2014; ГОСТ 4986-79
- grades: 12kh18n10t, 20kh13
- groups: korrozionno-stojkie-stali
- gosts: 5632-2014, 4986-79

## SEO_TITLE
Магнитится ли нержавейка: почему одна сталь липнет к магниту

## SEO_DESCRIPTION
Аустенитная нержавейка не магнитится, мартенситная и ферритная — магнитятся...

## H1
Магнитится ли нержавеющая сталь

## ANSWER
Прямой ответ 40–60 слов.

## KEY_FACTS
| Параметр | Значение |
|---|---|
| Аустенитные стали (12Х18Н10Т) | практически немагнитны |

## MAIN_TEXT
## Первый раздел
Текст...

## Второй раздел
Текст...

## FAQ
### Вопрос?
Ответ в 1–3 предложения.
```

### Поля META

| Ключ | Значение |
|---|---|
| `cluster` | один из: `Выбор и применение`, `Марки и сравнения`, `Технология и свойства`, `Расчёты и нормативы` |
| `updated` | дата в формате `ГГГГ-ММ-ДД`, идёт в sitemap как `lastmod` и в JSON-LD `dateModified` |
| `sources` | источники через `;` — выводятся в подвале статьи |
| `grades` | слаги марок через запятую (реальные слаги каталога, см. ниже) |
| `groups` | слаги групп по назначению |
| `gosts` | слаги ГОСТов из `src/data/gosts.js` |

`grades` / `groups` / `gosts` работают в обе стороны: на странице статьи это блок «Смотрите в каталоге», а на страницах марки, группы и ГОСТа — блок «Статьи по теме».

### Слаги каталога

Марки: `08kh18n10`, `10kh17n13m3t`, `12kh18n10t`, `12kh18n9`, `12kh18n9smr`, `17khngt`, `20kh13`, `27kkh`, `29nk`, `36nkhtyu`, `40kkhnm`, `65g`, `ei814-17khngt`, `kh15n60`, `kh15yu5`, `kh20n80`, `kh20n80-n`, `kh23yu5`, `kh23yu5t`, `khn78t`.

Группы: `korrozionno-stojkie-stali`, `lenta-holodnokatanaya`, `precizionnye-splavy`, `uglerodistye-stali`, `vysokoe-elektrosoprotivlenie`, `zharostojkie-i-zharoprochnye`.

## 4. Сборка и проверка

```bash
npm run build:articles
```

Скрипт падает с понятной ошибкой, если в файле нет строки `URL: /stati/<slug>/`, отсутствует обязательная секция или дублируется slug.

После сборки: `npm run dev` → `http://localhost:3000/stati/` и страница статьи. Проверяем, что h2 получили `id`, оглавление собралось, FAQ-аккордеон работает, JSON-LD валиден.
