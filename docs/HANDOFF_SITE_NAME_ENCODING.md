# Handoff: кракозябра «РљР°С‚Р°Р»РѕРі…» (site name / OG / Telegram)

Документ для следующего ассистента: что это за проект, что уже сделано, что **не сработало** после деплоев.

---

## 1. Проект (кратко)

- **Стек:** Node.js, Express, Nunjucks (шаблоны `.html`), MySQL (каталог металлопроката).
- **Репозиторий:** GitHub `moiseev1991-stack/lenta-stalnaja`, ветка `main`.
- **Прод:** `https://lenta-stalnaja.ru/` (иногда в логах/скринах — HTTP).
- **Что работает в целом:** SSR каталог, админка, выгрузки, главная с товарами; **нормальная кириллица** в `<title>`, `og:title`, hero `<h1>`, описаниях из БД (`home_title`, `home_h1`, `home_meta_description`).
- **Что ломается (симптом):** в одних и тех же страницах в **других местах** остаётся строка вида **`РљР°С‚Р°Р»РѕРі РјРµС‚Р°Р»Р»РѕРїСЂРѕРєР°С‚Р°`** — это типичный mojibake (UTF-8 прочитан как однобайтовая кодировка). Проявляется в:
  - `meta property="og:site_name"`
  - JSON-LD `WebSite` / `Organization` → поле `name`
  - `alt` у логотипа в шапке
  - копирайт в подвале `© …`
  - превью ссылок в Telegram (верхняя строка превью = site_name)

Ожидаемый текст везде: **«Лента стальная — каталог металлопроката»** (или эквивалент). Битая строка по смыслу соответствует **«Каталог металлопроката»** (короче, чем целевое название).

---

## 2. Откуда бралась битая строка (гипотеза)

- В БД в таблице `settings`, ключ **`site_name`**, значение когда-то записалось/читалось с неверной кодировкой.
- В **старых шаблонах** эти поля выводились как `{{ siteName }}` из `res.locals` / БД.
- При этом **`home_title`** и др. из той же БД на проде отображались **нормально** — значит проблема не «вся БД в latin1», а конкретно цепочка **`site_name` → шаблон** или дублирование разных источников.

## 4. Инфраструктура / почему правки могли «не доезжать»

- Пользователь заявлял: **деплой с GitHub подтягивается автоматически**; панель хостинга для ручного перезапуска Node **может быть недоступна** на тарифе.
- Страница админки «Восстановление базы» на **проде долгое время была без** блока «Деплой с GitHub» / кнопок перезапуска — т.е. **файлы на сервере отставали от репозитория** или **другой корень проекта**.
- **404 на `GET /admin/restart`** — на сервере не было актуального `admin.js` с маршрутом (или другой порядок роутов).
- Возможные причины, почему HTML не меняется после «деплоя»:
  - **Не перезапущен** процесс Node (старый код в памяти; Nunjucks **кэширует** шаблоны в production).
  - **Перед Node стоит кэш** (nginx `proxy_cache`, CDN) — отдаётся старый HTML.
  - Запущено **не то приложение** / не та директория / два инстанса.
  - Ответ HTML формируется **не этим Express** (редко, но стоит проверить).

## 6. Что имеет смысл проверить следующему ассистенту (чеклист)

1. **Фактический ответ сервера:** `curl -sS https://lenta-stalnaja.ru/ | head -n 30` — есть ли `og:site_name` с кракозяброй или с «Лента стальная…».
2. **Сервер тот же:** заголовки ответа, версия приложения (если добавить временный `X-App-Commit` в коде).
3. **Кэш:** отключить кэш для `/` или проверить с `Cache-Control: no-cache`.
4. **Один инстанс Node, перезапуск после pull.**
5. **Содержимое `settings.site_name`** в MySQL (hex/длина) и что реально подставляет Nunjucks в рантайме (лог на один запрос к `/`).
6. Если подмена в `res.end` не срабатывает — трейс: кто вызывает `res.write`/`res.end` (стриминг, compression).
